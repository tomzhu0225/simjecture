# Bounded elapsed-time observations while the worker is parked

The first new reference-runtime fault trajectory deferred at the observable
completion contradiction. Once the stream became quiet, no new decision was
submitted until the common fallback resumed the worker. This is retained in the
runtime comparison. Its eight trajectories continue unchanged.

Freeze a separate follow-up before its first outcome. At identical pinned base
weights, FLA-prefill runtime and native downstream policy, compare event-only
observation with an added public timed observation every 15 seconds while the
worker is parked. The timed observation contains actual elapsed parked time and
current process/receipt/adapter states; it contains no recommended action or
hidden case identity. It is suppressed while an authority job is active and stops
when the worker resumes. Ordinary completion probes and logs remain available in
both arms. No heartbeat promotes a scientific result or authorizes a repair.

Run healthy/adapter-defect × event-only/timed × two repeats: eight fresh native
worker trajectories, randomized by seed 2026102407 in opaque UUID directories.
Retain the same 90-second fallback, numeric criteria, two controls, worker-turn
and wall bounds. Retain all failures and late wakes. This is an exploratory fix
for a discovered observation gap, not a held-out confirmatory claim or training.

Start only after the eight runtime trajectories finish and all four sequential
servers release. Use one warmed model server, at most two parents, the shared
four-native-role/240-total-start lease and at least forty remaining start slots.
Record judge dispatch before/after fallback, first contradiction-to-judge time,
actual extra model calls, healthy false wakes, report verification, native starts,
required-feedback reconciliation and full task time. A useful result requires
more reliable fault detection without healthy repair wakes; report call overhead
whether or not the new observation helps. Rules already solve this explicit fault
faster, so success would only fix event-observation behavior, not prove a need
for ML or an RL improvement.
