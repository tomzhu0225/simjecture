# Paired public-checkpoint continuation pilot

Prospectively specified on 24 October 2026, before cohort collection. This
implements the collection gate in the [reward study](../monitor-reward-20261024/protocol.json).

Eight real native GPT-6 Astra workers each execute a bounded WarpX control.
After the worker exits, the host takes a quiescent artifact and public-transcript
checkpoint. Clearly recorded host diagnostic attempts expose an injected defect
where applicable. No private provider state or shared provider randomness is
claimed. Each continuation starts a fresh native session on the copied files
and the same public context. Runtime directory names are opaque UUIDs.

The eight checkpoint templates are healthy progress, a known negative charge
check, worker-repairable recursive analysis, repeated incorrect analysis
arguments, a warning about the next diagnostic mesh, an unexplained negative
charge check, a protected completion-adapter defect, and a restored adapter
whose earlier traceback remains in the transcript. The two negative-charge
templates differ in the available prior context. These are small engineering
investigations, not long-duration healthy workloads or new plasma discoveries.

For each checkpoint, run two repetitions of an intervention/wait pair: 32 parent
continuations. The route is specified by the public-evidence template before
outcomes, not by a learned model. Intervention types are director attention,
worker-help inference, and an independent repair judge. Randomize branch order
within each pair and the order of pairs; retain every native failure. Both
branches subsequently observe and honor explicit worker help/repair requests
under the same policy. There is no automatic monitor intervention after the
initial experimental choice. Prespecified actions are not on-policy PPO data.

Each continuation has 650 seconds, up to three parent turns of 220 seconds and
four recorded simulation slots, including inherited runs. Preserve field and
charge criteria 0.05 and 1e-11. Independent saved-plot analysis verifies all
reported numeric metrics, the pass/fail flags, coverage of saved runs and the
requested two configurations. Quality is 1 for an accurate complete report,
0.5 for an accurate partial report, and 0 for an absent or inaccurate report.
A correct negative scientific check is accepted. Protected wrappers, trusted
analysis, inputs and environment must retain their hashes. A changed bridge
requires an actual host-applied, fixed-test-verified grant with a matching hash.
This reporting/progress score does not establish general scientific validity.

Record actual native starts for all roles using one shared executable wrapper,
bounded to four concurrent native processes, two parent controllers, 12 starts
per continuation and 240 starts overall including commissioning and prefixes.
Each lease records Linux PID/start time, boot identity, start/end and return
code. A native role cannot recursively spawn unmetered experimental agents.
These same-account agents and bounds are cooperative, not adversarial isolation.

The durable ledger separates incident identity/generation, actual dispatch,
feedback availability, delivery and content-bound worker acknowledgment.
Applied protected repairs and director replans require reconciliation; ordinary
helper/director advice is advisory and does not force an extra worker turn
after an already complete report. Canceled requests with no actual result are
not feedback misses. Acknowledgment does not itself prove usefulness. Duplicate
wakes count concurrent identical route contexts or a repeated judge for the
same unchanged, host-tested repaired adapter. Separate judge/proposer/helper
roles are not duplicates merely because they concern one incident.

Use the existing decomposed utility and paired scorer unchanged. Report quality,
starts, elapsed time, acknowledgments and duplicate measurements separately;
show coefficient sensitivity. Missing components withhold a scalar. Timing
includes helper and cleanup waits and independent verification. Native agents
are stochastic and the local GPU has an unrelated ongoing simulation: do not
claim paired deterministic counterfactuals, isolated throughput or RL efficacy.

The commissioning prefix and repair continuation are excluded together, before
cohort collection. They exposed late stale requests and informed the collection
instrumentation. The executable design manifest fixes every UUID, intervention,
pair identity, order seed, configuration and checkpoint hash. Code must be
committed before starting cohort prefixes. Changes needed after collection
starts require an explicit retained amendment or a separate cohort.

Further model training is conditional on comparable complete measurements and
meaningful intervention-value variation. Eight templates alone cannot establish
task-disjoint generalization. Do not manufacture positive labels from judge
approvals or treat these fixed actions as logged on-policy samples. A future
SFT/RL comparison needs separate development/test task mechanisms and fresh live
worker outcomes. New Colab use is bounded to 40 compute units and three hours;
allocate only when an actual model experiment is justified, with a release guard.
