# Minimal default: evidence rules without a prescribed research schedule

The operator chose minimal as the preferred default after the v2 comparison.
This is a product/design choice, not a claim that the harder FLASH benchmark
proved a completion or token advantage. The default applies to new native-agent
studies through `simjecture study`, `simjecture-supervise` and
`simjecture-research`. Structured and frontier remain selectable. Existing studies
retain their mode and deadline. Legacy MVP, API/DSH and browser/TUI launchers
still use their existing formats; minimal browser integration is outstanding.

## Changes grounded in observed failures

| Observation | Change | Boundary |
|---|---|---|
| Adequate evidence could be stuck in administrative stages | Agent owns the plan; review enforces scientific outcomes | No compulsory plan review or instrument hierarchy |
| Prototype omitted explicit counterexample search | Support requests cite challenge strategy, experiments and outcome | Exhaustive finite-domain tests qualify; no extra phase required |
| All repairs previously pointed to root | Immutable parent links support branching and nested repairs | Ancestor counterexample evidence accompanies review |
| “Meaningful repair” did not require minimal change | Prospective repair explains why each change is necessary | Reviewer judgment, not a word-count or mathematical minimality guarantee |
| A review confused original and repair dispositions | Explicit target claim ID and statement retained | Host separately determines study completion |
| Large solver batches lost partial usefulness on timeout | Prompt recommends pilot schema checks, independent long cases and budgeting | Agent chooses the decomposition; no imposed job graph |
| Repeated context consumed tokens | Compact status by default; full metadata on request; short native-thread resume prompts | Full scientific instructions remain in a durable guide |

A repair can be prepared before its parent's review concludes, avoiding an
artificial scheduling dependency. Acceptance of repair support requires accepted
falsification of every ancestor. Existing experiments cannot be retrospectively
converted into validation; the source/arguments and acceptance rule are frozen
before new evidence is generated. Numerical uncertainty is not falsification.
Counterexample source/results are rechecked for integrity when descendant
reviews are assembled. Multiple generations do not recursively duplicate all
ancestor packets.

The hypothesis tree is an evidence structure, not a Git worktree manager.
Native working files remain flexible; each recorded experiment already owns an
isolated snapshot. Keeping one physical checkout per claim would add machinery
without evidence that it improves these tasks.

## External references and how they influence this design

Anthropic's [Building effective agents](https://www.anthropic.com/engineering/building-effective-agents)
argues for simple composable patterns and distinguishes prescribed workflows
from model-directed agents. This supports retaining agent control while using a
small service for durable evidence. It does not prove Simjecture's performance.

Anthropic's [Writing effective tools for agents](https://www.anthropic.com/engineering/writing-tools-for-agents)
recommends evaluating tools on realistic tasks and making concise versus detailed
responses available. That informs compact status with full receipts on demand,
and measuring actual runs rather than treating reduced text as a success metric.

Takahara and Mizoguchi's [Hypothesis Evolution Protocol preprint](https://arxiv.org/abs/2607.09195)
proposes explicit auditable hypothesis generation, evaluation and evolution.
Its abstract reports materials-science experiments. The relevant design parallel
is durable hypothesis/evidence ancestry; those reported results are not evidence
for our plasma tasks or justification for adding a mandatory orchestration layer.

## Compatibility and validation

New minimal records use scientific-policy schema 2. Existing schema-1 studies
remain readable under their original host requirements; no historical outcome is
rewritten. Resume rejects an explicit mode change or changed original hypothesis.
Native tools remain available and numerical experiments retain Bubblewrap.
Same-account cooperative access is still not an adversarial security boundary.

Validation combines invariant tests (including nested failures and forged
challenge references), CLI routing/resume tests, the full regression suite,
and fresh token-accounted GLM Euler/midpoint studies. Follow-up fixes to resume
compatibility and packet construction are separately regression-tested; frozen
live trial source is retained so outcomes are not silently attributed to a
later implementation. No new hard-task superiority claim follows from this
iteration; the previous one-hour FLASH results remain the relevant limitation.
