# Pre-dispatch help feedback declarations

Prospective validation after the checkpoint and parked-worker studies finished.
Their original outcomes remain unchanged. The strict audit found six completed
continuations in five pairs with unacknowledged help and no declared necessity.
Those scalars remain withheld; the new interface cannot relabel past intent.

Add an optional `feedback_requirement` to `lab.request_help`: `required` means
the caller needs the result reconciled before finalizing; `advisory` means
optional assistance. Omission preserves the old request body/hash and leaves
legacy necessity unspecified. A declaration is part of the immutable request
and frozen helper context before dispatch. Reusing a key with another declaration
fails. It never grants scientific approval or execution/repair permissions.
An operator may require declarations for a new study through
`helper_policy.require_feedback_requirement`; existing studies default to the
legacy behavior. This records intent; ordinary production report finalization
does not acquire a new automatic blocking gate.

The experimental ledger honors declared required results and records
content-bound acknowledgments. Automatically inferred monitor assistance is
declared advisory; only the capable roles determine subsequent work. Future
checkpoint continuations reject a changed downstream contract before launching
native work. Historical collector revisions remain available for replay.

Run four fresh native GPT-6 Astra investigations: two required-help and two
advisory-help tasks, randomized in an opaque host manifest. Each runs the actual
64/40 and 128/80 WarpX controls and asks for a bounded temporary helper's source
assessment with a NOTES.md artifact. Required tasks import and acknowledge that
artifact before finalization; advisory tasks may finish without another turn
solely for optional advice. Scientific checks remain 0.05 and 1e-11. Verify
saved-plot metrics independently and verify imports against actual helper hashes.

Use the existing shared four-native-role/240-start lease, at most two parent
controllers, 650 seconds and up to three worker turns per task. Retain failures
and unknown measurements. This validates measurement and backward compatibility;
it is not an RL rollout cohort, a counterfactual comparison, or evidence of new
model capability.
