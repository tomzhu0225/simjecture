# Simjecture 科研决策模型实验协议

本协议依据 2026 年 11 月 16 日的本次需求建立。科研效果的判断分别使用科学结论正确性 C 和实验决策能力 D。基模固定为 `Qwen/Qwen3.5-9B`，修订固定为 `c202236235762e1c871ad0ccb60c8ee5ba337b9a`。该公开 checkpoint 已经过厂商后训练，本文中的“未训练 9B”指尚未接受本项目 SFT/RL 的这个原始 checkpoint。模型原始配置包含视觉编码器，本项目输入为结构化文本，视觉编码器保持冻结。[模型配置](https://huggingface.co/Qwen/Qwen3.5-9B/blob/main/config.json)

## 科研任务与隔离

训练集 80 题，开发集 16 题，测试集 20 题。四个难度等级分别包含 20、4、5 题。训练集等离子体 64 题、跨领域 16 题，开发集 13 与 3 题，测试集 16 与 4 题，合计 93/116 题为等离子体问题，占 80.17%。任务文件包含研究问题、竞争解释、方程、初边界条件、参数范围、初始配置、候选求解器、诊断与总时间预算。

训练集同一研究族的四个等级始终处于同一划分。开发集使用 16 个不同研究问题，其中压力各向异性问题在统计时合并为一个机制组。测试集包含 20 个不同机制问题。分组使用问题与因果机制，MHD、PIC、PDE 等通用方程和求解器可以跨划分共用。正式启动前必须复核相邻机制的概念重叠，尤其是训练集均匀 Alfvén 传播与开发集非均匀相混合、不同流体和动力学闭合，记录任何合并决定。合并只调整统计组，跨划分实质同源问题必须在冻结前替换。

测试的具体题面、参数、随机种子、参考约束和未来验证条件采用 AES-256-GCM 加密保存。研究进程仅在测试开始时获得当前题面的公开部分，评估端保留隐藏参考与后续验证配置。密钥位于工作包之外的操作员目录，部署包排除密钥、测试明文、教师私有推理及评审内部材料。研究者和训练服务的远程文件系统中不放置密钥。

任务当前属于已编制命题，物理算例可执行性与独立参考的数值精度需要在获准启动后的资格验证中确认。测试已知题的隐藏内容包括解析约束或独立参考求解规范，复杂耦合题仍需补齐经过资格验证的参考执行程序。密封题的参考程序不在普通准备包内公开。

开发集与测试集中的任何状态、动作、回执、报告或评分都禁止进入 SFT/RL 数据。开发集标量评测用于选点和停止。任务划分文件与内容哈希一起冻结。正式测试只执行一次协议化比较，测试反馈无法回流到模型选择。

## 总时间预算与真实研究过程

暂定四级研究总预算依次为 1、3、6、12 小时。这组预算是本次准备采用的可审阅默认值。模型可自由决定单次实验时长、实验次数、网格、粒子数、模型层级和精度。单次运行的默认终止时刻应为研究总截止时刻，模型可主动提前停止。主机的实际内存、CPU/NPU 与储存容量仍是资源边界。

总预算包含推理等待、排队、仿真、诊断、研究过程审查及阶段性报告。独立终局复算在额外的评估预算中执行并计入总研究成本，四个处理组使用相同复算规则。模型在截止前动态保留报告时间。遇到超时、数值错误、目标未达成或计算规模不足，均须按已获得的真实证据输出已证实、已证伪、尚未解决的内容、适用范围与不确定性。到期后的整理只允许读取截止时刻前已封存证据，新增科学计算进入独立复核记录。

每次实际执行使用全新的研究分支和执行目录，记录源代码、配置、求解器及编译版本、随机种子、输入输出哈希、真实开始结束时间、执行状态和资源成本。失败与部分结果保留。已有公开 Simjecture 案例用于流程设计和证据要求，任务内容由本协议的物理问题确定。[Simjecture](https://github.com/tomzhu0225/simjecture)

## GPT-6.1 Sol 与 9B 的职责

Director、Worker、Reviewer、教师和终局匿名评审均使用 GPT-6.1 Sol。代码生成、工具调用、物理推理、最终结论与独立科学审查继续由这些实例负责。Reviewer 使用独立会话。终局匿名评审实例从未参与对应研究。

9B 的动作包含实验选择、系列实验组织、参数设置、模型层级和计算规模分配。默认优先执行 9B 给出的仿真规模。Director 或 Worker 修改时，逐项记录 9B 原始 JSON、修改理由、原始及最终参数与规模、实际执行源代码和输入哈希，以及建议到执行回执的关联。完全由大模型制定的决定标为接管。混合决定按选择、组织、参数、层级和规模五个分量记录来源。

9B 输入由字段白名单构造，只包含当前研究合同、竞争假说、物理模型、可用资源、已完成的真实回执、必要历史证据和剩余预算。未完成实验的预测结果、未来验证配置、参考答案、教师私有推理和评审分数不得写入输入。公开参数理由属于监督目标，教师内部推理属于独立私有材料。奖励仅供优化器使用，后续观察不携带分数。

## SFT 与在线 RLOO

先在 80 个训练命题上各收集 3 条完整教师研究轨迹，共 240 条。三种示范侧重证伪、多精度资源配置和竞争机制辨别。教师根据真实执行结果更新计划。240 条指完整研究轨迹，每条包含数量不定的决策训练样本。准备阶段只生成收集清单，实际回执和示范数据在实验开始后产生。

SFT 只学习结构化状态到公开决策 JSON 的映射，助手目标位置参与损失。LoRA 初始 rank=64、alpha=128、dropout=0.05，覆盖语言模型的全注意力、Gated DeltaNet 线性注意力投影以及 MLP。参数名必须在实际模型中匹配并覆盖两类注意力层。视觉、词嵌入及输出头冻结。初始 16K 输入上下文和 1536 输出 token 属于容量起点，出现溢出时重新构造有证据引用的状态，重要证据禁止静默截断。

在线 RLOO 每组从同一训练问题、同一初始状态和预算采样 4 条完整研究轨迹。组内保持旧策略快照固定，策略更新发生在四条轨迹都结束并完成阶段性结论之后。相同实验签名使用可配对的随机流，各分支分别执行实际仿真。教师轨迹、旧数值轨迹和其他策略的执行输出无法替代在线实验。初始每组更新一次，不设置总更新步数。两张 NPU 同步 LoRA 梯度，基座保持冻结，参考策略为同一基模上的冻结 SFT adapter。

轨迹收益包括去重后的可信证据增量、有效证伪、竞争解释区分、参数与资源合理性，以及终局证据支持的规律或新假说。科学收益初始采用过程 0.30、终局 0.70，资源效率仅在科学有效性相当时作最多 0.02 的有界调节。有效反例必须通过对应的数值控制。重复输出同一证据无法重复得奖。未经验证的假说保留为未解决事项。捏造回执、无依据结论会扣分。

基础 RLOO 优势使用整条轨迹收益 `A_i=R_i-mean(R_j,j!=i)`，无需 value critic。多轮行为保留证据到实际决定及其因果上游的关联。完全接管决定的正向收益为零。混合决定仅保留实际执行的学生来源部分，终局收益使用保守的来源归因代理，并明确该代理的统计偏差。不同后续状态、不同回合索引的收益禁止直接拼成同状态的 LOO。需要更细过程归因时，从同一真实状态复制分支再使用 LOO。正式建议归因实验提供独立的处理效应估计。[RLOO 方法](https://huggingface.co/docs/trl/rloo_trainer)

目前保存了双 NPU LoRA 训练器、模型服务、真实回执与 SFT/RL 导出、奖励、轨迹一致性、LOO、C/D 评估及停止组件。双 NPU 合成输入已通过 16K 输入加 1536 目标 token 的前后向与完整 LoRA 梯度同步。在线研究调度、模型服务切换、独立评审和自动奖励回传的完整联调仍待完成。

## 开发评测、停止与检查点

每累计 80 条完成的 RL 研究轨迹触发一次 16 题开发评测，SFT 初始化时另评测一次。一次均衡首轮 RL 覆盖 80 个训练问题的 4 样本组，共 320 条轨迹。因此耗时情景中的 n=4、8、16 对应至少一、二、四轮完整覆盖，实际停止由开发结果决定。

每个开发题先保存一个原版 Simjecture 固定基线，再让各候选检查点使用同题、同初值、同随机流、同权限和总预算进行配对研究。原版 16 次基线可固定复用到所有候选比较中，保留执行日期及负载。检查点是否优于当前最佳点使用与当前最佳点的配对比较，原版基线比较单独监控，避免同一绝对收益反复重置停止计数。

分别保存 C、D、按机制组泛化、条件策略多样性、建议采纳比例、大模型修改和接管比例、每项有效证据及每个 C/D 点的计算成本。策略多样性按同类状态中的动作分布和证据适应性判断。科学合理的收敛策略可以保留，多样性下降且证据适应性受损才标为坍缩。

初始可靠提升标准是相对当前最佳点的配对 C 改善区间下界超过 2 分，且 D 区间下界超过 -2 分，同时保留机制组泛化。上述阈值是准备采用的预注册默认值。第 j 次评测消耗 `0.05/[j(j+1)]` 的显著性额度，C/D 各分配一半。使用机制组 bootstrap 近似区间并同时报告原始配对分布和区间分辨率，重复查看开发集仍存在有限样本和适应性选择误差。16 题的小样本无法保证检出微小改善。

连续 4 次缺乏可靠提升，或检测到可靠的泛化退化、确认策略坍缩时停止，选择满足科学正确性及 D/泛化约束的最佳检查点。数值训练故障即时保存并停止更新诊断。开发集改善时继续训练，n 和 m 按实际执行记录确定。

## 正式比较与建议归因

正式比较在 20 题上各运行原版、原版+原始 9B、原版+SFT 9B、原版+SFT/RL 9B，共 80 次完整研究。共享版本固定的 Simjecture、仿真工具、GPT-6.1 Sol 权限、研究题面、初始物理状态和每题总预算。处理顺序按题随机化，CPU 队列、研究预算和负载控制一致。不得让一个处理组使用另一组新产生的科学结果。

建议归因另设 20 对分支，共 40 次配对研究。每题在正式原版研究的一个预注册决策点复制当前状态，只保留当时已有的真实证据。两个分支分别由 GPT-6.1 Sol 独立决策，或先接收最终 9B 建议再决策。随机流、剩余预算、可用工具和资源相同，后续分别真实执行。主分析为是否提供建议的 intention-to-treat 效应，另报告实际计划差异、规模建议采纳、后续证据增益、C/D 和修改比例。只有 20 对时报告效应与不确定性，完全接管比例高将反映在建议贡献和纠错依赖中。

已知题 10 个，使用隐藏参考约束、独立求解和新条件预测检验。开放题 10 个，使用独立验证实验和独立复算评价可靠性。独立 GPT-6.1 Sol 实例以随机匿名报告评估潜在创新性与科学价值。创新性辅助分单列，无法替代 C 的证据评分。

## 独立百分制评分

|评分|项目|满分|评分证据|
|---|---|---|---|
|C|参考真值一致性或开放任务证据有效性|40|逐项结论的真假、效应、不支持项和适用条件，开放任务使用实际支持与反例|
|C|独立复算与新条件预测|35|独立求解器或独立实现、不同离散与新配置复核，预注册预测与复算回执|
|C|数值可信度、范围和不确定性|25|空间时间及统计收敛、守恒与收支、边界、误差及未知项|
|D|实验选择及竞争解释区分|30|干预设计、可区别预测、信息增量和有效证伪|
|D|参数、分辨率与计算规模|25|尺度解析、参数选择、物理模型适用性、快速扫描与精算升级|
|D|根据新证据调整策略|25|更新依据、停止错误路线、对反例的修正和纠错成本|
|D|系列实验组织与总资源配置|20|依赖、并行、验证预算和总体时间分配|

所有研究都进入两项评分。未完成研究按已有结论与证据覆盖程度计分。未验证的结论无法获得验证分，诚实陈述未解决事项可以获得对应的范围、不确定性与决策分。评分表保留分项分、对应证据 ID 和理由。C、D 各自满分 100，最终并列报告。

结局指标包含有效科学发现与证伪、理论边界修正、独立复现率及每单位 CPU 核时、GPU/NPU 时、总墙钟和大模型 token 成本的收益。复现率的分母为提交复核的可检验结论，另报所有运行的证据产出率，防止通过少提交结论提高复现率。缺失评分、执行失败和时间耗尽均列入全样本结果。

## 资源与准备状态

优先采用现有远端双 64GB Ascend 910。已核实远端可见 40 个 CPU 逻辑核，容器总配额约 36 核、内存约 229GiB。准备配置给训练保留 CPU 0–3，仿真使用 CPU 4–35 和最多 128GiB 内存。仿真与训练共享物理主机，使用独立 CPU 分配，远端暂未发现 GPU。仿真环境使用已有 Athena++ 和 WarpX 26.11，涉及扩展物理的算例须由 Worker 在同样预算与版本政策下实现并进行资格审查。FLASH 在官方来源需申请代码，当前流程使用现有求解器准备任务。[WarpX 安装](https://warpx.readthedocs.io/en/latest/install/users.html) [Athena++](https://github.com/PrincetonUniversity/athena) [FLASH 获取方式](https://flash.rochester.edu/site/flashcode/)

本机保留准备文件、加密密钥和可选的轻量控制入口，本机科研仿真及训练默认关闭。现有旧项目 NPU 服务占用约 9GB HBM，资源就绪记录需保留这一事实。两卡 NPU 的 Qwen3.5 混合注意力前向、反向、采样概率重算、adapter 保存恢复和分布式同步属于后续资格验证项目。公开 Ascend 文档支持多种模型和训练后端，具体 910 型号、CANN、训练框架和这个模型的组合需以实际资格验证为准。[Ascend 文档](https://verl.readthedocs.io/en/latest/ascend_tutorial/en/)

## 采样与训练数值路径校正

准备期合成采样检查发现缓存生成和整段回放之间存在数值差异，四个 token 的序列 log 概率差最大约 0.0781。训练器保留实际采样分数，使用整条轨迹的采样与回放概率比进行重要性加权，初始上限为 2，并记录 log ratio、截断比例和有效样本量。截断会引入偏差，需要在真实长轨迹联调时验证其影响。RLOO 的四样本留一基线和科学收益归因保持独立记录。[数值路径校正方法](https://verl.readthedocs.io/en/latest/algo/rollout_corr.html)
