# 训练方法与运行命令

本目录提供科研决策训练层，Simjecture主程序位于仓库 `src/conjecture_solver`。训练只使用Qwen3.5-9B。以下命令不会在GitHub CI中自动启动。

## 环境配置

使用Linux/WSL控制端、2×64GiB Ascend910训练节点和独立CPU仿真节点。两个远端当前要求采用相同的本目录绝对路径。各节点克隆本分支，以 `/srv/simjecture` 为例。控制端：

```bash
cd /srv/simjecture/research/decision_training
python3.12 -m venv .venv
.venv/bin/python -m pip install -e '../..[process]' jsonschema cryptography
chmod +x bin/*
export PACKAGE="$PWD"
export PATH="$PACKAGE/bin:$PATH"
export PYTHONPATH="$PACKAGE:$PACKAGE/../../src${PYTHONPATH:+:$PYTHONPATH}"
.venv/bin/python tools/configure_local.py \
  --remote-root /srv/simjecture/research/decision_training \
  --training-host training-node --simulation-host simulation-node \
  --case-store /srv/simjecture-cases
```

`training-node`、`simulation-node`为已配置的OpenSSH别名。该命令只生成忽略于Git的本机配置。GPT路径另需Codex CLI、其相邻的`codex-code-mode-host`/`rg`、本地登录文件与bubblewrap，在`isolation.local.json`填写实际路径；纯自主训练不需要GPT登录。普通Linux默认直接联网，可选Windows代理桥。案例存储使用Linux文件系统或支持Unix metadata的挂载。

实测依赖见[validated-runtime.json](docs/validated-runtime.json)：CANN9.0.0、torch2.7.1+cpu配合torch_npu2.7.1.post4、Transformers5.14.1、PEFT0.18.1。先使用Ascend匹配的torch/torch_npu，再安装`requirements-npu.txt`。官方接口见[Qwen模型页](https://huggingface.co/Qwen/Qwen3.5-9B)和[Transformers文档](https://huggingface.co/docs/transformers/model_doc/qwen3_5)。

在NPU节点创建专用入口，路径按实际安装调整：

```bash
python3 tools/configure_remote.py training \
  --python /opt/decision-venv/bin/python \
  --cann-env /home/developer/Ascend/cann/set_env.sh \
  --ld-preload /lib/aarch64-linux-gnu/libgomp.so.1 \
  --driver-lib /usr/local/Ascend/driver/lib64/driver \
  --driver-lib /usr/local/Ascend/driver/lib64/common --cpu-affinity 0-3
```

ARM环境的`libgomp`设置来自本次实测。在CPU节点准备安装了本仓库与NumPy/SciPy的环境：

```bash
python3 tools/configure_remote.py cpu --python /opt/simulation-venv/bin/python \
  --cpus 16 --memory-mb 24576
```

NPU主机若同时提供独立CPU分区，也在该主机配置`cpu-python`，按实物使用`--cpu-affinity 4-35 --cpus 32 --memory-mb 131072`。控制端只登记实际可用的执行池：

```bash
bin/controller-python tools/register_worker.py --id independent-cpu --cpus 16 --memory-mb 24576 --check
# 第二个CPU分区准备好后才登记：
bin/controller-python tools/register_worker.py --id remote-cpu --cpus 32 --memory-mb 131072 --check
bin/controller-python scripts/lab_rpc_process.py start
```

Lab控制服务只管理预留与回执，物理求解仍在远端。更改执行池只影响新研究，既有研究的执行池、任务与截止不可修改。

## 唯一基模和资格检查

NPU节点可链接已有权重至`models/Qwen3.5-9B`，或显式下载固定修订：

```bash
resources/training-python tools/model_files.py --directory models/Qwen3.5-9B --download
resources/training-python -m torch.distributed.run --nproc-per-node=2 --master-port=29617 \
  scripts/qualify_npu_runtime.py --root "$PWD" --tokens 512 --target-tokens 64 --check-roundtrip
```

已有文件时省略`--download`，仍逐文件校验SHA。长上下文可用`--tokens 20480 --target-tokens 4096`检查16k输入+4k输出。合成检查会使用NPU，但不产生科研数据或真实训练更新。原环境已通过该长度、LoRA全梯度同步和约42.6GiB/卡显存检查；换依赖后需重新资格验证。

## 一、GPT示范 → LoRA SFT

训练目标是公开结构化科研决定，禁止GPT内部推理、开发/测试题或隐藏参考进入SFT。完整计划240条真实研究，每条包含数量不固定的决策，且关联真实执行回执与独立质量审查。

控制端完整收集入口如下。运行记录绑定协议哈希；配置命令本身不启动实验：

```bash
bin/controller-python tools/authorize_stages.py collect-sft sft online dev
bin/controller-python -m research_decision.pipeline collect-sft
```

不足240条合格轨迹会退出，不能虚构或重复填充。已有案例可用`research_decision.collect --help`导出。把实际JSONL传至NPU节点后：

```bash
resources/training-python -m research_decision.preflight_data \
  --base models/Qwen3.5-9B --config config/training.json \
  --data data/sft/decisions.jsonl --output data/sft/eligible.jsonl
resources/training-python -m torch.distributed.run --nproc-per-node=2 --master-port=29617 \
  -m research_decision.train_adapter sft \
  --base models/Qwen3.5-9B --config config/training.json \
  --data data/sft/eligible.jsonl --output checkpoints/full-sft
```

过滤无效、行政或超上下文的决策不等于剔除其科研研究；研究仍完整参加C/D。过滤后还需复核240条轨迹覆盖。默认2轮、r64/alpha128、BF16；冻结视觉、embedding和lm_head，训练语言混合注意力与前馈投影。小规模先导使用`config/pilot-training.json`，不能充作完整240条。

## 二、不消耗GPT额度的自主RLOO

这是已实际执行更新的路径，必须有真实SFT检查点。当前固定工具`MHD1D`支持T01-L1的一维理想MHD平滑周期Alfvén波，9B选择网格、参数、扫描、时长与收敛检查；不支持任意求解器自动生成。

控制端创建新计划并启动后台流程：

```bash
bin/controller-python tools/init_pilot.py \
  --initial /srv/simjecture/research/decision_training/checkpoints/full-sft/sft-epoch-2 \
  --total-hours 20 --rl-hours 2.5 --study-seconds 900
bin/controller-python scripts/pilot_deadline_process.py start
bin/controller-python scripts/autonomous_pilot_process.py start
bin/controller-python scripts/autonomous_status.py
```

默认仅自主训练；若训练后还要GPT主导四组对照，在初始化时增加`--with-comparison`。恢复必须沿用原计划，不能重置研究时钟。

每组4条完整研究：固定旧策略→真实CPU仿真→数值规则→停止采样服务→两卡RLOO→保存adapter/优化器/各卡RNG/哈希→下一组。900秒是研究总预算，不限制单次仿真、次数或网格；2.5小时是此先导的采集窗口，不是固定更新次数或完整方案的收敛判断。

规则、原始建议、修改、执行和成本全部记录。学生观察不含目标参考值、评分、奖励或未来结果。规则C/D仅为保守诊断，独立复算分项为0，不替代最终独立评估。失败、超时和未完成研究全部保留并形成阶段性结论。

```bash
bin/controller-python scripts/autonomous_pilot_process.py status
bin/controller-python scripts/pilot_snapshot.py --autonomous
```

正常窗口结束会保存当前更新并停止采集。紧急停止控制器不等于远端任务全部取消，应使用`pilot_deadline`的逐项目清理流程保留终局回执；按PID、启动时间和项目进程组识别，不影响其他项目。

## 三、GPT主导的完整在线RLOO

Director/Worker/Reviewer仍由GPT-6.1 Sol主导，9B提供建议，规模优先采用9B建议。修改、否决与执行逐项记录，完全接管不给学生正向信用。

```bash
bin/controller-python -m research_decision.pipeline online \
  --initial /srv/simjecture/research/decision_training/checkpoints/full-sft/sft-epoch-2
```

实现按80训练题均衡采集，每组4条，每80条训练轨迹评估完整16开发题；持续改善则继续，连续4次无可靠改善、泛化退化或策略坍缩时停止并保留最佳点。C优先且D受约束，两项分开报告。全80题的求解器/独立参考尚未逐题资格验证，当前先导不能替代完整开发结论。

四组为原版、原版+原始9B、原版+SFT9B、原版+最终RL9B，题目、工具、权限和总预算一致。单题pilot只做描述比较。正式20×4和建议归因20×2的实现位于`test_campaign.py`，需训练停止并冻结模型、评分和顺序后使用；已知结论客观评价模块尚待补齐，当前不能宣称正式测试完整可运行。

## 恢复、部署和数据复用

SFT增加`--resume checkpoints/full-sft/sft-epoch-1`。RLOO低层恢复示例：

```bash
resources/training-python -m torch.distributed.run --nproc-per-node=2 --master-port=29617 \
  -m research_decision.train_adapter rloo \
  --base models/Qwen3.5-9B --config config/training.json \
  --data data/rloo-inbox --output checkpoints/full-rloo \
  --initial checkpoints/full-sft/sft-epoch-2 \
  --resume checkpoints/pilot-autonomous-rloo/rloo-update-000002
```

低层更新器等待真实同策略组及`actors-stopped`交接回执，单独启动不会生成研究轨迹。通常优先使用在线调度器的`--resume`；完整调度还需完整16题开发基线。复制完整检查点目录与manifest，不能只拷adapter就声称恢复优化器/RNG。旧策略轨迹不能冒充新策略在线数据；保留同任务、初态、预算、策略哈希及真实行为概率。损失使用token级截断重要性校正和来源掩码，是带偏差的条件代理目标，独立贡献另由配对归因检验。

固定建议服务：

```bash
resources/training-python -m research_decision.policy_service \
  --base models/Qwen3.5-9B --config config/training.json \
  --device 0 --arm simjecture_sft9b --adapter checkpoints/full-sft/sft-epoch-2 --port 19190
```

原始基线使用`--arm simjecture_raw9b`并省略adapter；RL使用`simjecture_sftrl9b`和真实RL检查点。同一NPU的采样与更新互斥，由调度器停启，不要重复启动已有服务。
