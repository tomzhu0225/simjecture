# Ordinary Python experiments

Use `run_python` for contained calculations supported by the ordinary Python
environment. Prefer a short workspace script over a large inline `-c` program
when the calculation, diagnostics, or audit trail is nontrivial. Make the script
write a compact JSON summary with the exact scalar fields named by the evidence
contract; retain supporting tables or figures only when they help audit the
result.

## Contract boundary

- Register the evidence contract before running the observation. After an
  insufficient adjudication, a later contract version may prospectively name a
  different test, but only fresh evidence produced under that version can decide
  the claim.
- For ordinary `run_python`, omit `execution_binding` and
  `additional_execution_bindings`. Also omit capability-only fields such as
  `capability`, `program_path`, `program_sha256`, `commissioning_argv`, and
  `allowed_scientific_argv`. There is no generic capability named `python`;
  execution bindings belong to named external capabilities run through
  `run_evidence_capability`.
- In ordinary scientific `validation_checks`, provide `json_path` and the exact
  scalar `expected_value`, and normally omit `aspect`. The `aspect` field is only
  for the fixed commissioning vocabulary: `interface`, `representation`,
  `physics_controls`, `boundaries`, `diagnostics`, or `numerical_regime`; it is
  not a free-form label.
- Give every mutation and execution a stable assignment-prefixed
  `operation_id`. Reuse an ID only for an exact retry.
- Set `observation_sufficient=true` when a linked artifact actually satisfies
  the active contract. This flag records contract compliance; it does not let
  the Falsifier declare the scientific claim supported. A surviving claim still
  requires independent adjudication.

## Evidence loop

1. State the observable, competing outcomes, decision rule, coverage,
   uncertainty criterion, and inconclusive conditions before observing the
   result.
2. Write or reuse the smallest script that directly tests that rule. Reuse
   already accepted facts and artifacts during judge-directed follow-up work;
   do not repeat unrelated literature or environment discovery.
3. Call `run_python` with the script path as the first `argv` item and the open
   scientific claim as `active_claim_id`. The harness waits on the returned
   durable job; do not issue repeated `job_status` calls during a healthy wait.
4. Inspect the terminal report and artifact contents. A successful process is
   not by itself scientific evidence.
5. Link only tracked artifacts generated by the successful job. Record whether
   each observation satisfies the active contract and why. Close a scientific
   claim as falsified only for an accepted contracted counterexample; surviving
   evidence goes to independent adjudication.

Do not infer installed packages. If an optional library is missing, use the
available NumPy/SciPy or standard-library route when scientifically adequate,
or preserve a durable blocker. Do not silently weaken a universal claim to a
sampled-grid statement; either add a validated enclosure or analytic argument,
or register an explicitly resolution-bounded scientific refinement.
