# 0.5.3 stable scope and validation

This release brings the 0.5.3 candidate series into one stable version. Minimal
remains the default; structured and frontier modes are still selectable. The
installer preserves research data, provider settings, installed instruments and
older program folders.

## Included behavior

- Local/SSH numerical workers with recorded job identity, CPU/RAM/GPU admission,
  asynchronous execution, verified artifact retrieval and interruption recovery.
  The Machines page supports basic SSH setup, advanced settings, agent preparation
  and independent 30-second availability checks. Research agents and scientific
  review remain on the coordinator.
- The measured coding-agent leaderboard, task-specific time/cost ranks, visible
  unfinished costs and Pareto tradeoffs. Custom trials and contributed grades are
  separate from the maintained official edition. These tasks analyze recorded
  diagnostics; they do not launch new FLASH or WarpX simulations.
- Campaign recovery, request-level usage records and native DeepSeek tool-message
  continuity, with bounded evidence retrieval by independent reviewers.
- The independently audited ledger, reserved-CPU accounting, worker transport,
  input validation and conversation repairs described in the
  [rc4 acceptance record](0.5.3rc4-acceptance.md).
- Shared Conversation → Study → Evidence & review navigation. A selected study
  survives reloads, mode changes and monitor Back/Forward navigation. Continuation
  returns to the owning conversation when there is one; standalone studies remain
  inspectable without creating a conversation during read-only access.
- Protection against stale study replies and duplicate continuation submission.
  Leaving a pending continuation preview frees the action immediately; its late
  response cannot reopen or replace a newer dialog, even after returning to the
  original route.
- Workspace-first onboarding, a provider-neutral headless recipe, a shorter
  contribution guide and an archive for dated reports. No publication-authorship
  policy is adopted.

## Release checks

The final stable package is in preparation. Validation results will be recorded
here against the integrated release commit before publication. The navigation
repair has already passed 1,045 Python tests with seven optional-runtime skips,
including eight real Chromium navigation cases; those are component checks,
not a claim that the final stable package has passed all release checks.

## Limits

This release retains the research strategy, independent scientific review gates,
completion contracts and benchmark task pack 0.3.0. It introduces no new model
benchmark measurements or claims of improved scientific delivery. The release
checks do not substitute for a new long GPU/FLASH/WarpX research campaign.

Cooperative PRoot is not an operating-system security boundary; numerical sandbox
settings do not enclose native agent host tools. Optional runtimes must be
commissioned on the actual worker and execution path. Passing an execution or
interface check does not establish numerical convergence or physical validity.

Standalone continuation submission still has no durable retry receipt for an
ambiguous lost HTTP response. Repeatedly submitting after such a loss can create
another conversation. The new dialog guards do not claim to solve that case.
